# mosidas.dev の機能マップ

このディレクトリには mosidas.dev の利用者から見た振る舞いと、それを実アプリで確かめる操作を機能ごとに書く。操作の前に本書を読む。次に該当する機能ファイルを開く。

## 共通の前提

- [mosidas.dev の検証の手引き](../README.md) の 1. の手順で起動し、2. の健康診断がすべて ok である。
- 操作するシェルで `RUN_ID` を設定し、`. "docs/verify/runs/$RUN_ID/run.env"` で `$BASE` と `$EVIDENCE_DIR` を読み込んである。
- コマンドはリポジトリのルートで実行する。
- 画面の一覧は作業ツリーの `src/data/` のファイルから作る。up はデータを取得しないので、表示は作業ツリーの内容のとおりである。
- この実行で起動していないインスタンスを操作しない。別の実行のインスタンスは、その実行の証拠と状態を持つ。

## 操作の約束

- 前提に別の指定が無ければ、各手順を共通の前提の状態から始める。
- ブラウザーの操作は `docs/verify/scripts/drive.mjs browser "$RUN_ID"` に続く操作の列で書く。1 回の呼び出しは新しい Chrome で始まるので、各列を `open` から始める。
- セレクターは id・role・aria の属性・data 属性・ルートのパス(`href` の値)で書く。class の名前と DOM の位置を使わない。
- ページの変化は決まった秒数で待たない。`until` で変化した後の状態を待つ。
- 機能ファイルの観測する結果は、browser の呼び出しが終了コード 0 で終わったことを前提にする。`ng` の行が出たら [mosidas.dev の検証の手引き](../README.md) の 2. の健康診断を実行する。
- コマンドは書かれたとおりに実行する。引用符とセレクターを変えない。
- HTTP の要求は [mosidas.dev の検証の手引き](../README.md) の 3. の curl のコマンドで送る。`Origin: https://mosidas.dev` を付けて、証拠を `$EVIDENCE_DIR/<機能 ID>/` に保存する。
- 後始末で証拠を削除しない。

## 証拠と省略の報告

- 利用者の操作とその結果の状態を取る。最後の画面だけでは足りない。
- 画面の証拠は `shot` のスクリーンショット(PNG)と `text` で保存した `innerText` の 2 つである。
- HTTP の証拠は curl の状態コードと応答の本文である。
- 副作用の証拠は `wrangler.log` の要求の行と Worker のログの行である。要求を送らない機能では、`grep -a -c '\] [A-Z]* /api/' "$EVIDENCE_DIR/wrangler.log"` が 0 であることを証拠にする。
- 証拠は `evidence/<機能 ID>/` に保存する。使った入口は `browser.log` の `open` の行に残る。
- 証拠には機能の ID と使った入口を書く。
- 届かなかった経路は試したコマンドと満たせなかった前提を書いて報告する。
- 別の経路で通したことを届かなかった入口の合格として報告しない。

## 機能ファイルの形

各機能ファイルは H1 の題と利用者から見た振る舞いの 1 段落で始める。続けて次の 4 つの H2 を持つ。順は変えない。

1. `サブ機能`: 短い ID と 1 行の振る舞いを並べる。
2. `利用者からの到達`: 利用者の入口をすべて並べる。
3. `操作`: `前提:` で始める。利用者の操作・正確なコマンド・観測する結果を組にしたラベル付きの箇条を続ける。
4. `落とし穴`: 検証の時間を無駄にするか結果を無効にする罠を並べる。

実装の詳細を書かない。書くのは利用者の経路・安定した手掛かり・必要な状態・コマンド・観測できる証拠だけである。
